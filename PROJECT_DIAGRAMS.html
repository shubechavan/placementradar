9Sequence: sign-in

Failed attempts are counted before the password hash runs, so guessing is throttled. Accounts live in a separate auth database.

sequenceDiagram
  autonumber
  actor U as User
  participant UI as Browser app
  participant API as /api/auth/login
  participant RL as rate_limit
  participant AU as auth.py
  participant ADB as Auth database
  U->>UI: email + password
  UI->>API: POST credentials
  API->>RL: allowed for this IP and email?
  alt too many recent failures
    RL-->>API: blocked
    API-->>UI: 429 try again later
  else allowed
    API->>AU: verify
    AU->>ADB: find active user
    AU->>AU: PBKDF2 hash check
    alt valid
      AU-->>API: user, role
      API->>RL: clear failure count
      API-->>UI: signed session cookie
    else invalid
      API->>RL: record failure
      API-->>UI: 401
    end
  end
  Note over UI,API: every later call carries the cookie, and a 401 sends the app back to sign-in

12Activity: identity resolution

A company name alone is not an identity. A website is accepted only when the page itself names the company.

flowchart TB
  S(["Company name"]) --> K["Build company key
distinctive words only"]
  K --> G["Guess candidate domains"]
  G --> C{"Corroboration gate:
page title, site name or footer
names the company?"}
  C -- yes --> OK(["Keyed domain:site
confirmed identity"])
  C -- no --> F["Fallbacks: other suffixes,
short-name domain,
Wikidata official website"]
  F --> C2{"Gate passes?"}
  C2 -- yes --> OK
  C2 -- unclear --> RQ[["Human review queue"]]
  C2 -- no --> KEY(["Stays keyed key:name
until evidence appears"])
  RQ -- "approved" --> OK
  RQ -- "rejected" --> KEY

Measured result: companies with a usable website went from 21.2% to 53.3% after automated resolution and to 61.4% after human review.

15Contact confidence scoring

Each contact gets a score from independent evidence, clamped to 0 to 1. The interface shows a simpler A to F grade per company.

EvidenceEffect on score
Email on the company's own confirmed domain (or a phone from an ATS)+0.30
Found through an applicant-tracking-system source+0.25
Names a specific person+0.20
Role title is HR, talent, recruiting, campus, people, hiring, staffing or personnel+0.15
Mailbox verified over SMTP / only the domain's MX record checked+0.20 / +0.05
Generic role address (info@, contact@ ...)-0.15
Personal provider (Gmail, Yahoo ...) with no person's name-0.20
Came from an aggregator or directory (JustDial, IndiaMART, Sulekha, TradeIndia ...)-0.25
Same value seen on more than one company (shared switchboard)spread penalty
ResultSum clamped to 0.0 to 1.0; 0.6 or above is eligible for bulk send, the rest is manual review
Grade (company view)MeaningPoints
APhone and email, with an HR-type address80 or more
BPhone and email55 to 79
COnly a phone or only an email35 to 54
DCompany website only15 to 34
FNo contact details yetbelow 15

Grade points: phone +35, email +35, company website +15, HR-type email +15.
